# Agent Guidance: Helious Quantum

## Architecture
- **Portal (`heros/`)**: separate self-contained project — `heros/index.html` is the entry page „HELIOUS“ with top buttons to **HEROS** (`/heros/trade.html`, търговията), HELIOUS terminal (`/index.html`) и HERMES (`/hermes.html`). Served at `/`, `/heros`, `/heros/` (see `server.js`); terminal shortcut: `/helious`. Търговията е брандирана **HEROS**, а порталът/сайтът — **HELIOUS**.
- **Single-page app** with a zero-dep Node.js proxy server (`server.js`).
- **UI**: `index.html` (inline CSS, scripts split under `js/`). **Forecast engine**: `forecast.js`.
- **Frontend modules**: `js/config.js` (constants/symbols), `js/state.js` (shared state), `js/data.js` (fetchKlines), `js/news.js` (news view), `js/indicators.js` (RSI + indicator data), `js/app.js` (main app: chart, present line, realtime). Tab algorithms live in `js/tabs/`: `tabs.js` (registry + shared helpers), `indicators.js`, `average.js`, `historical.js`, `logistic.js`, `markov.js`, `expected-value.js`, `wavelet.js`, `fourier.js`, `rsi-phase.js`, `candle-forecast.js` — each registers a `renderPanel`/`drawChart` pair into `TabRegistry`.
- **Models**: `models.js` (statistical probability models: historical, logistic regression, Markov chain, expected value, wavelet, FFT). **Data provider**: `data-provider.js` (symbol normalization, multi-source data fetching, MT5 bridge).
- **Paper trading engine** (`engine/`): `strategy.js` (чиста логика вход/изход/размер — огледало на HERMES `simulate()`), `symbolSpec.js` (contract size по инструмент → реален обем в **лотове**, който се показва в UI и се ползва за P/L; минималният обем/стъпка се задава в UI, по подразбиране **0.01** лот; **спред за минималния обем** — параметър `minLotSpread` (€), важи САМО когато позицията се отвори на минимума (`lots <= minLot`): сумата става начална плаваща загуба, като входната цена се отмества с `shift = minLotSpread / (lots × contract)` в полза на загубата (BUY нагоре, SELL надолу), а TP/SL се смятат от отместения вход, така че R:R се запазва); оразмеряването отчита **свободния маржин** (`equity − зает маржин`) и никога не отваря позиция с по-голям маржин от него, `paperBroker.js` (виртуална сметка, позиции, P/L, маркери; маркерите се режат до 5000 за дълга 24/7 работа), `session.js` (live loop на всеки затворен бар: тегли барове → `computeModelProbSeries` → вход/изход; пауза/резюме/стоп; SSE). API под `/api/paper/sessions...`. UI: `heros/trade.html`. `models.js` вече се импортира и в Node (CommonJS export в края + `computeRSI`). Сесиите се записват в `data/paper-sessions.json` (Docker volume) и се **възстановяват автоматично** при старт (`engine/session.init()`), т.е. продължават да търгуват независимо дали е отворен сайтът/браузърът. Всяка сесия носи `ownerId` (профилът, който я е стартирал) — `GET /api/paper/sessions` връща само неговите сесии (+ `active:[id]`), а `/api/paper/sessions/:id` отказва чужди (освен legacy сесии без owner); `DELETE /api/paper/sessions/:id` трие спряна сесия. `getState()` връща и `contract` за всеки символ (UI го ползва за същата проверка на спреда). `heros/trade.html` при зареждане вика `loadSessions()` → минава **автоматично към последната активна сесия** (`attach(id)`): пълни параметрите от конфигурацията ѝ, отваря SSE и показва актуалното състояние; панел „Моите сесии“ (статус, капитал, P/L, брой сделки, ✕ за изтриване) позволява ръчно превключване. Ако вече има активна сесия, „Започни търговия“ пита и спира старата, за да не се дублират.
- **Auth**: `auth.js` пази профили и токени в `data/auth.json` (scrypt хешове, cookie `heros_auth`). `/api/auth/register|login|logout|me`. `heros/trade.html` и `/api/paper/*` изискват вход; `heros/login.html` е екранът за вход/регистрация.
- **CDN dep**: Lightweight Charts 4.1.1 (`unpkg.com`). `package.json` съдържа само `pg` (за Docker/PostgreSQL); за локален dev без БД не е нужен `npm install`.
- **UI language**: Bulgarian (`lang="bg"`). All labels, tooltips, and notifications are in Bulgarian.
- **Server** (`server.js`): Static file serving + `/data` endpoint (unified data via `data-provider.js`), `/news` endpoint (RSS Google News→Bing + keyword sentiment), plus legacy `/binance`, `/yahoo`, `/ticker` endpoints.

## Data Flow
1. Client calls `fetchKlines(symbol, interval)` → `/data?symbol=X&interval=Y`
2. `data-provider.js` resolves symbol aliases (e.g. DAX → Yahoo:^GDAXI, MT5:GER40)
3. Tries sources in order: MT5 → Binance Futures → Yahoo Finance
4. Returns normalized candles `[{time, open, high, low, close, volume}]`

## Symbol Aliases
Defined in `data-provider.js` `SYMBOL_ALIASES` table. Canonical names: DAX, NDX, SPX, DJI, CAC, UK100, NI225, EURUSD, GBPUSD, XAUUSD, WTI, BRENT, BTCUSDT, ETHUSDT... Any alias resolves to canonical. Search via `/symbols?query=...`.

## Commands
- **Start (dev)**: `node server.js` (listens on `PORT` env var or `3001`). DB е изключена, ако няма `pg`/`DATABASE_URL`.
- **Deploy (Docker)**: `cp .env.example .env` → попълни → `./deploy.sh` (build без кеш + стартиране). `./deploy.sh restart|logs|down`.
- **DB migrations**: SQL файлове в `migrations/` (напр. `001_init.sql`), прилагат се автоматично при старт на `server.js` чрез `migrate.js`; приложените версии са в таблица `schema_migrations`.
- **Docker**: `docker-compose.yml` — `app` (Node, порт **48081**, volume `./data:/app/data`) + `db` (PostgreSQL 16, volume `pgdata`). `Dockerfile` тегли кода от GitHub (build args `GIT_REPO`/`GIT_REF`); `entrypoint.sh` при всяко стартиране прави `git fetch/reset` (ако `AUTO_UPDATE=1`), чисти npm кеша, преинсталира при промяна и пуска `node server.js` (→ миграции).
- **MT5**: Install `MetaTrader5` Python package → `pip install MetaTrader5`. Run `python3 mt5-bridge.py --check` to verify. (**Windows-only**; не работи в Linux контейнера.)
- **Tests**: Start server first, then `node scratch/test_endpoints.js` or `node scratch/test_commodities.js`.
- **Health**: `GET /health` (използва се от Docker healthcheck; показва и статуса на DB).

## Key Behaviors & Quirks
- **Realtime**: Frontend polls every 5s via `/data`. Forecast NOT re-run on poll — only on explicit triggers (selection change, period change, force reload, present-line drag).
- **No background work**: Heavy math runs ONLY when its view is actually visible (`chartViewVisible()` / `indicatorViewVisible()` / `appVisible()` in `js/app.js`). Realtime polling is stopped via `visibilitychange` when the tab is hidden and resumes + refreshes on return (`onMarketViewReshown`). `ivReload()`/`updateIvPanel()` skip everything when the dashboard is hidden (cache is nulled → lazy reload on open); `updateIndicatorCharts()` computes model probability sequences only on the chart view and only for the ACTIVE page (`computeIndicatorModelProbs` page→model map); tab panels render only the current page (`renderCurrentTabPanel`, called on `onIvPageScroll`). `computeModelProbSequence` is cached by `candlesHash` (`modelSeqCache`). Opening a view may therefore cause a short wait.
- **Present line**: Draggable vertical line. Drag backwards to lock cutoff → ALL prediction models (candle forecast, FFT overlay, indicator/model sequences and the tab panels) are recomputed using only candles up to that line (`candlesUpToCutoff` / `recomputePredictions`), ignoring data after it. Double-click to reset to live; changing the time frame or symbol also resets the cutoff and recomputes for the new frame.
- **RSI phase tab** (`js/tabs/rsi-phase.js`, page 8): Each period (10м/30м/1ч/4ч/1д/7д/30д) fetches its OWN candle interval (1m/5m/15m/1h/1h/4h/1d) via `/data`, computes RSI, finds alternating peaks/troughs (only values beyond |RSI-50|≥10, strictly alternating max/min, most extreme kept among same-type neighbors). Per period: absolute amplitude (max−min), avgMax/avgMin/avgMid, phase in degrees (−180 at min / 0 at mid / +180 at max). Final output = weighted sum of (phaseDeg × relAmp) → aggregate phase, and aggregate RSI index = 50 + phase/180×50. On this page the FFT forecast overlay is hidden; the RSI peaks (▲) and minima (▼) are drawn on the indicator canvas below the chart. Data is cached per symbol+interval.
- **Candle forecast tab** (`js/tabs/candle-forecast.js`, page 9): Uses ALL candles up to the present-line cutoff (not just visible). Weighted average of previous candles' PERCENTAGE bodies (close−open)/open·100, signed, with EXPONENTIAL weights `A(t)=A0·e^(−βt)` (damped): newest has the greatest weight, older decay; `t` is normalized age (0 newest … 1 oldest), β default 0.5 (range 0.01..1; 0.01 = near-equal weights, 1 = max decay), adjustable via `#candleBetaSlider` in the top bar (visible in both chart and tab views). Forecast = lastClose + weightedAvg; repeated for the next 10 candles (forecast bodies feed back into the window). When the chart is opened from this panel, the 10 forecast candles are drawn ON the main price chart via `candleForecastSeries` (cyan up / purple down). Data is loaded as 2× the period limit: the extra half is history so every visible candle has an equal look-back (`candleForecastLookback` = period limit). The FFT forecast overlay AND the FFT spectrum row (`#fftSpectrumRow`) are hidden here. Two strips are shown below: (1) `#chartIndicatorCanvas` = candle MOVEMENT (real body % + 10 forecast bars), and (2) `#candlePredictionCanvas` = the rolling predicted % for every visible candle (`rollingForecastPct`), with a % scale and ▲/▼ markers for the max/min, plus a hover tooltip (`onPredictionHover`); both are positioned by `timeToCoordinate` so they scroll/zoom with the chart. The present-line label shows the SUM of the 10 forecast movements as % (`candleForecastTotalPct`). On other pages the forecast series is cleared and the FFT row restored.
- **Force reload**: "Презареди Прогнозата" resets forecast state, unlocks present line, reloads all data.
- **Hermes bot simulator** (`hermes.html`, opened via `openHermes()`): Standalone page using `models.js`. Candle interval (`#inpInterval`, 1м..1Д) + optional date range (`Времеви период` / `Бързи дати`: Днес/3Д/7Д/30Д/Всичко); fetch limit auto-covers the range at that interval. Clicking the symbol badge (`#hSymbol`) opens a search box (`#symSearch`, `/symbols?query=`) → `selectHermesSymbol()` sets `currentSymbol` and re-runs. `Скорост` (`#inpSpeed`, candles/sec, 0 = instant) drives LIVE playback: `prepareSimChart()` shows the chart at the period start and `liveTick()` slides the visible range, draws new `tradeMarkers` and updates the `#liveStats` bar (change from start €/% · balance · total · trades · open · volume/margin/notional (— when flat) · candle) as `simulate()` runs; the `#currentPos` open-positions panel stays permanently visible and shows dashes when flat (no open/close flicker). At the end `renderSimChart()` fits the whole period. Below the price chart a parallel canvas (`#simPnlCanvas`, `drawPnlChart()`) shows the account change in % from the start, centered on a 0 line with a self-scaling % frame (`equityPct[]`, `niceScale()`), aligned to the chart time axis and updated on every live tick. Trade markers: arrowUp/arrowDown for BUY/SELL opens, colored circles for closes (TP/SL/Време/Край + P/L in €). When model = „Средна вероятност“ (5) the `#contraBox` menu appears with a per-model „контра“ checkbox; `computeModelProbSeries(candles, 5, {invert:[...]})` flips Buy↔Sell for the selected components before averaging. `Кели (макс. фракция)` defaults to `0.05`. Оразмеряването е в **лотове** (contract size по инструмент, `SYMBOL_SPECS`; минималният обем се задава с полето „Мин. обем (лот)“, по подразбиране **0.01**; до него „Спред за мин. обем (€)“ (`#inpMinLotSpread`) — сумата в € се отчита само за позиции на ОЗНАЧЕНИЯ минимален обем, отместеният вход е `close ± (спред / units)`; `#minLotSpreadHint` live показва отместването в пункта/%, а при `shift > min(tpDist, slDist)` предупреждава, че позицията ще излезе веднага на SL/TP (иначе изчислява безопасния таван в €) и е ограничено от **свободния маржин** (никога не отваря позиция с по-голям маржин от наличните пари); обемът в лотове се показва в панелите и на маркерите. Панелът `#currentPos` е постоянно видим, с фиксирана височина и еднаква структура (при липса на позиция редът е с тирета) и показва зает/свободен маржин — така графиката не мърда.
- **Period configs** (`periodConfigs` in `js/config.js`): Map UI labels to `interval` + `limit`.
- **Custom symbols**: Added via search box are persisted in `localStorage` key `helious_custom_symbols`. Also resolved via data-provider alias table.
- **Port override**: `PORT` env var works (`server.js:6`). Tests assume `3001`.
